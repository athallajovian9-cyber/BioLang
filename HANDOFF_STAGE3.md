## Architecture of Stage 3: Tree Execution Without Native Maps

BioLang has no native hash map type (`Dictionary<K, V>`). In `selfhost/parser.bio` and `selfhost/lexlib.bio`, lookups are handled through:
1. `colony` of `membrane` structures scanned linearly, or
2. Parallel colonies (`colony names`, `colony values`).

### 1. Core Structures (`selfhost/eval.bio`)
```bio
membrane Value {
    dna typeKind    // 0=void, 1=dna, 2=rna, 3=enzyme, 4=colony, 5=membrane, 6=closure
    dna numVal      // For dna numbers
    rna strVal      // For rna strings
    enzyme boolVal  // For enzyme booleans
    colony listVal  // For colony elements
    dna objId       // Reference index for membranes
    dna fnIndex     // Function / closure pointer
}

membrane Scope {
    colony names    // colony of rna
    colony values   // colony of Value
    colony mutFlags // colony of enzyme (fossil vs cell)
}

membrane Env {
    colony scopes   // colony of Scope (stack of scopes)
}
```

### 2. Execution Flow
1. **Load & Register**: Scan AST `organism` functions, `membrane` blueprints, and `trait` contracts.
2. **Execute Top-Level**: Execute top-level variable declarations and statements into the root global scope.
3. **Run `nucleus()`**: Execute the statements of the entry block.
4. **Expressions & Operator Evaluation**:
   - Arithmetic: `+`, `-`, `*`, `/` on `dna`.
   - String concatenation: `+` on `rna`.
   - Comparison: `<`, `<=`, `>`, `>=`, `==`, `!=`.
   - Colony indexing and methods (`.length`, `.inject()`, `.slice()`, `.sort()`).
   - Function calls (`organ` invocation, parameter binding, lexical closures).
